# Expected-skip manifest — every test allowed to NOT run, and why.
#
# Enforced by scripts/ci/check_no_undeclared_skips.sh (see that file's header
# for the mechanism and for the surfaces it deliberately does not cover).
#
# Format, one entry per line:
#
#     <surface>|<test-id>|<skip-reason>|<expected-count>
#
#   surface         haven-core | rust_builder | flutter — reconciled
#                   independently, so a haven-core row is never reported stale
#                   while checking rust_builder.
#   test-id         Rust:  <cargo target>::<libtest name>, where the target is
#                          `src/lib.rs`, `tests/<file>.rs`, or `doc` for
#                          doctests (whose churning `(line N)` suffix is
#                          stripped — the item path is the stable identity).
#                   Dart:  <package-relative suite path>::<full test name>.
#                   A trailing `*` makes it a prefix glob.
#   skip-reason     The reason VERBATIM: `#[ignore = "..."]` for Rust (empty for
#                   a doctest, which has no message), `skip:`/`skipReason` for
#                   Dart. Matched exactly — the reason is the gate, so a gate
#                   that silently changes cause must not pass.
#   expected-count  Optional; defaults to 1. REQUIRED on a glob, so a group
#                   entry pins how many tests it covers instead of quietly
#                   absorbing the disappearance of all but one of them.
#
# Regenerate the raw rows with:
#   scripts/ci/check_no_undeclared_skips.sh --list cargo <cargo-test.log>
#   scripts/ci/check_no_undeclared_skips.sh --list dart  <test-report.json>
#
# ===========================================================================
# ADDING AN ENTRY IS A DECISION, NOT A FORMALITY.
#
# Every skip below is gated on an ENVIRONMENT fact — a D-Bus Secret Service, a
# Blossom server, a generated ARB, `Platform.isAndroid` — not on anything in a
# diff. That is what makes them safe to declare and dangerous to leave
# undeclared: the set can change from underneath a PR that never touched a
# test. Before adding a row, establish that the proof is not simply LOST:
# either the same invariant is proven by a sibling test that does run (say so,
# and name it), or the skip is a genuine capability gap that belongs on the
# manual pre-release checklist.
#
# Removing a row is equally load-bearing: it means the test runs again. Deleting
# a row for a test that still skips fails the build, which is the point.
# ===========================================================================
