# Per-path coverage floors — the minimum each security- or privacy-critical
# path may fall to, and the level past which it must be re-pinned.
#
# Enforced by scripts/ci/check_coverage_floors.sh (see that file's header for
# the mechanism, the ratchet, and why a stale entry is a hard failure).
#
# Format, one entry per line:
#
#     <stack>|<path>|<floor-percent>[|<ratchet-margin>]
#
#   stack     rust (haven-core) | flutter (haven) — reconciled independently,
#             so a rust row is never reported stale while checking flutter.
#   path      Relative to the STACK ROOT. A trailing `/` means "directory" and
#             AGGREGATES every file beneath it; anything else is a glob over the
#             file path. Directory and file rows deliberately overlap: the
#             directory catches slow layer-wide drift, the file row catches one
#             critical file being hollowed out while its neighbours compensate.
#   floor     Whole percent. Line coverage — the same metric the 80%/50%
#             aggregate gates use, read from the same lcov report.
#   margin    Optional. Points above the floor at which the run fails asking for
#             a re-pin. Defaults to 5; raise it only for a path so small that
#             one line is worth several points.
#
# Regenerate every row against a fresh report with:
#   scripts/ci/check_coverage_floors.sh --list rust    haven-core/coverage.lcov
#   scripts/ci/check_coverage_floors.sh --list flutter haven/coverage/lcov.info
#
# ===========================================================================
# LOWERING A FLOOR IS NOT A FIX.
#
# These numbers exist because the 80%/50% gates are AGGREGATES, and an
# aggregate is a budget the whole crate shares. When this file was pinned,
# haven-core had ~2290 lines of slack over its 80% gate and haven had ~1588
# over its 50% — enough for any single file here to fall to zero with the gate
# still green. A row that goes red is telling you a specific proof stopped
# running; editing the number down converts a measured regression into a
# permitted one and leaves nothing behind to notice it again.
#
# The legitimate reasons to EDIT a number are: the ratchet asked you to raise
# it (do so, using the value in the failure message), or the path genuinely
# moved (update the pattern — do not delete the row, an entry matching nothing
# fails on purpose).
# ===========================================================================
#
# All values below were measured on 2026-08-03 from
#   cargo llvm-cov --all-features --lcov --ignore-filename-regex 'frb_generated'
#   flutter test --coverage
# and pinned at floor(measured) - 2, or exactly 100 where the path is fully
# covered (see the guard header: the margin rule cannot ratchet a 100% path).
